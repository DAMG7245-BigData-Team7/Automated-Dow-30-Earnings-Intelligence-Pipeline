What Worked Well

1. Multi-Strategy IR Page Discovery

The IR extractor achieved 100% success rate (30/30 companies) in finding investor relations pages through a comprehensive multi-strategy approach. The system intelligently tried subdomain patterns first (successful for 29 companies), then fell back to link navigation when needed. This redundancy ensured no manual intervention was required, with verification scores averaging above 75 for most companies.

2. Robust Web Scraping Architecture

The file downloader's aggressive approach with multiple fallback strategies proved highly effective. The system handled various website structures by:

  • Implementing comprehensive cookie consent handling for OneTrust, TrustArc, and Quantcast frameworks
  • Using scroll-based lazy loading to capture dynamically loaded content
  • Following "Learn More/Read More" detail pages to access nested documents
  • Prioritizing document types intelligently (10-Q > press releases > presentations > supplements)

3. Efficient Resource Management

The pipeline's use of ProcessPoolExecutor for parallel processing within individual stages (particularly in the Docling parser with 3 concurrent processes) balanced performance with system stability. The sequential DAG structure in Airflow ensured dependencies were properly managed while allowing for parallel execution where beneficial.

4. Cloud Storage Integration

The S3 upload component successfully organized 1,146 files (53 raw, 1,093 parsed) totaling 178MB across properly structured directories. The dual-path storage strategy (raw-documents/ and earnings-documents/) maintained traceability while optimizing for different access patterns.

Challenges Faced

1. Website Heterogeneity

Each company's IR site required unique handling strategies. Companies like AMGN, Goldman Sachs, Microsoft, and Visa needed specialized navigation logic. While the special strategies worked, maintaining these company-specific implementations could become a scalability challenge as the system expands beyond the Dow 30.

2. Dynamic Content and JavaScript-Heavy Sites

Several IR pages relied heavily on client-side rendering, requiring Selenium with careful timing management. The balance between wait times (2-3 seconds per page load) and reliability meant the full pipeline took considerable time to complete. Some sites required multiple scroll cycles to trigger lazy-loaded content.

3. Document Extraction Precision

Without hardcoded years, the system had to rely on heuristics to identify the latest quarterly reports. While the ranking system (based on document type, position, and keyword matching) worked well, there's inherent uncertainty in whether the "latest" document found is always the most recent quarterly report, especially for companies that organize content unconventionally.

4. Resource Constraints

The Docling parser's computational intensity became apparent when processing larger PDFs. The decision to process only the smallest PDF per company was a pragmatic compromise but meant potentially missing richer data in larger documents. The parsing phase alone generated over 1,000 derivative files from 53 source documents.

How to Extend This Project Further

1. Enhanced Document Intelligence

  • Implement date extraction: Parse document contents to extract and validate report dates, ensuring true recency
  • Add OCR capabilities: Enable force_ocr in Docling for scanned documents
  • Expand document types: Include Excel files and HTML reports that some companies prefer
  • Implement document deduplication: Use content hashing to avoid reprocessing identical files

2. Scalability Improvements

  • Implement Airflow pools: Better manage concurrent company processing with resource pools
  • Add retry logic with exponential backoff: Make the pipeline more resilient to temporary failures
  • Create a company metadata service: Centralize company-specific strategies in a configuration system
  • Implement incremental processing: Track processed documents to avoid redundant downloads

3. Data Quality and Validation

  • Add data quality checks: Implement Great Expectations or similar framework to validate extracted data
  • Create automated testing: Build test suites for each company's IR page structure
  • Implement monitoring and alerting: Set up alerts for extraction failures or data anomalies
  • Add manual review interface: Create a simple UI for human validation of ambiguous extractions

4. Advanced Analytics Integration

  • Connect to downstream analytics: Feed parsed data into financial analysis pipelines
  • Implement NLP processing: Extract key financial metrics and sentiment from earnings calls
  • Create a comparison engine: Build tools to track quarter-over-quarter changes
  • Add competitive intelligence: Expand to industry peers beyond the Dow 30

5. Infrastructure Enhancements

  • Containerize the solution: Package each component in Docker for better portability
  • Implement distributed processing: Use Celery or Ray for true distributed execution
  • Add caching layer: Implement Redis for caching IR page structures and document metadata
  • Create API endpoints: Expose the pipeline's capabilities through a REST API

Conclusion

This project successfully automated a complex, multi-stage process that would typically require hours of manual analyst work. The 100% success rate in IR page discovery and successful processing of companies demonstrates the robustness of the approach. While challenges remain around handling website heterogeneity and ensuring document currency, the modular architecture provides a solid foundation for future enhancements. The pipeline's ability to adapt to different website structures without hardcoding makes it particularly valuable for scaling to additional companies beyond the Dow 30.
